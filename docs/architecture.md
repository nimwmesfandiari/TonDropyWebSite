# معماری

```
 Telegram (Mini App / Widget / Bot)
        │ initData / webhook
        ▼
┌──────────────── Cloudflare Worker ────────────────┐
│ /api/v1/*  → router → routes → services/lib       │
│ سایر مسیرها → Static Assets (frontend/)           │
│ scheduled  → jobs (قیمت، واریز، تطبیق حساب)       │
└───────┬───────────────┬───────────────┬───────────┘
        ▼               ▼               ▼
    D1 (SQLite)    KV (نرخ‌ها،      R2 (تصاویر KYC)
    ledger/سفارش   rate limit)
        ▲
        └── Toncenter API (واریز on-chain) / CoinGecko (قیمت TON)
```

## اصول طراحی

1. **ledger اول**: هر تغییر موجودی دقیقاً یک `UPDATE balances` + یک `INSERT ledger_entries` در یک `DB.batch` اتمیک است. قیدهای `CHECK` اجازه موجودی منفی به کاربران نمی‌دهند و ایندکس‌های unique جلوی اجرای دوباره (واریز، قفل/آزادسازی برداشت) را می‌گیرند.
2. **پول = عدد صحیح**: واحد کوچک هر دارایی (TON: ۹ رقم، USDT: ۶، تومان: ۰). محاسبات با BigInt و گرد کردن همیشه به نفع صرافی.
3. **حساب خانه (`user_id = 1`)**: طرف مقابل همه معاملات. موجودی آن می‌تواند منفی شود (ریسک موجودی/inventory)؛ تطبیق حساب هر ۱۰ دقیقه بررسی می‌شود.
4. **انسان در حلقه برای خروج پول**: برداشت‌ها فقط درخواست و قفل می‌شوند؛ ارسال واقعی خارج از سیستم و با تایید دستی انجام می‌شود. **هیچ کلید خصوصی‌ای روی Worker نیست.**
5. **قیمت قفل‌شده**: quote با TTL کوتاه، یک‌بارمصرف (`orders.quote_id UNIQUE`).

## جریان یک خرید

`POST /orders/quote` → ذخیره quote → `POST /orders` → یک batch شامل: درج سفارش، دو حرکت کاربر، دو حرکت خانه، (اختیاری) پاداش رفرال، اعلان. هر خطا کل batch را rollback می‌کند.
